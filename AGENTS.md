# Финансовый ассистент

> Учебный проект. Владелец учится разрабатывать с AI-агентом по методологии из `docs/guide.md`.
> Текущий прогресс и контекст: `docs/journey.md`.

## Режим наставника (действует, пока не завершён шаг 6 пути)

- В начале каждой сессии прочитай `docs/journey.md`: определи текущий шаг и продолжай с него.
- Объясняй **что** делаем и **зачем**: коротко, простым языком. Владелец — новичок (раньше только вайбкодил).
- Команды Git (`status`, `add`, `commit`, `switch`, `push`, PR) владелец выполняет **сам**. Давай команду с объяснением, но не выполняй её за него, если он явно не попросит.
- Решения (скоуп, архитектура, стек) принимает владелец. Ты предлагаешь 2–3 варианта с плюсами и минусами.
- Не забегай вперёд: не пиши код приложения, пока не готовы ТЗ (шаг 2) и архитектура (шаг 3).
- После завершения шага или подшага обнови `docs/journey.md`: отметь чекбоксы, добавь запись в журнал сессий.
- В конце сессии кратко: что сделали, чему научились, что дальше.

## Процесс разработки (главный цикл, подробно: docs/guide.md)

1. Ветка `feat/<имя>` → 2. `specs/NNN-<имя>/spec.md` → ревью владельцем →
3. `plan.md` + `tasks.md` → 4. каждая задача в новом чате по TDD (тест падает → код → тесты зелёные) →
5. ревью diff → коммит → 6. PR → CI зелёный → merge → 7. ретро: уроки в раздел «Уроки» ниже.

## Стек и команды

**Стек:**
- Язык: Python 3.12+
- Веб-фреймворк: FastAPI
- Бот: aiogram 3.x
- БД: PostgreSQL + SQLAlchemy
- Линтер/Тестирование: flake8 / pytest
- Субагенты: ВСЕГДА использовать максимальную модель (`pro` / 3.8 high) для делегирования задач по коду.

**Команды:**
- Установка зависимостей: `pip install -r requirements.txt`
- Запуск тестов: `pytest`
- Проверка кода: `flake8 src tests`
- Запуск API: `uvicorn src.main:app --reload`

## Запреты

- НЕ храни секреты (API-ключи) в коде: только `.env` (он в `.gitignore`).
- НЕ коммить реальные банковские выписки: они лежат только в `data/private/` (в `.gitignore`). Для тестов используй синтетические данные.
- НЕ изменяй существующие тесты без явного разрешения.
- НЕ выходи за рамки текущей задачи.

## Уроки (пополняется после ретро)
- **TDD (Test-Driven Development):** Сначала пишем падающий тест (Red), затем минимальный код (Green). Это гарантирует, что весь код покрыт тестами и делает то, что от него ожидают.
- **Виды тестов:** Unit-тесты проверяют отдельные детальки (например, модель данных), а Интеграционные — всю цепочку целиком (парсинг файла в список моделей).
- **Линтеры (flake8):** GitHub Actions не пропустит код, если он оформлен не по стандарту PEP8 (например, импорты не в начале файла). Автоформаттеры вроде `autopep8` и `isort` экономят кучу времени.
- **Мокирование (Mock):** При тестировании платных или медленных API мы используем "моки" (`unittest.mock`), чтобы имитировать ответы серверов и тестировать наш код локально бесплатно.
- **Переменные окружения (.env):** Секреты (API ключи) никогда не должны попадать в код (они в `.gitignore`). Но нужно всегда помнить: если код использует секреты, то CI/CD пайплайнам в GitHub тоже нужно передавать тестовые ключи или замоканные переменные, иначе тесты упадут при импорте.
- **Деплой ботов (TelegramConflictError):** При перезапуске бота на сервере нужно обязательно делать паузу (`sleep 3`) между убийством старого процесса (`pkill`) и запуском нового. Иначе Телеграм заблокирует запросы с ошибкой `TelegramConflictError`, решив, что один бот запущен дважды!
