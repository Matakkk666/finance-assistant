# Спецификация (Feature 002: Интеграция LLM для категоризации)

## 1. Суть фичи
Нейросеть (Gemini) будет принимать список неразмеченных транзакций (только что извлеченных из CSV-файла парсером), анализировать поле "описание" и присваивать каждой транзакции одну из наших утвержденных категорий. 

## 2. Требования
- Использовать официальный SDK от Google (Gemini API) или прямое HTTP-обращение.
- API-ключ должен читаться **только** из переменных окружения (`.env` файла). В коде ключей быть не должно.
- **Вход**: список объектов `Transaction` (у которых `category` пока равна `None`).
- **Выход**: тот же список объектов, но поле `category` заполнено.
- **Промпт**: Нейросеть должна получить четкую инструкцию с перечнем доступных категорий (Самокаты, Крипта, Виза заграничная, Хавка, Фастфуд, Рестораны, Озон, Веб3, Переводы, Прочее).
- Нейросеть должна вернуть результат в структурированном виде (JSON), чтобы мы могли легко программно сопоставить ответ с нашими объектами.

## 3. Технические детали
1. **Модель данных**: 
   - Обновить `src/models/transaction.py`: добавить опциональное поле `category: str | None = None`.
2. **Сервис LLM (`src/services/llm.py`)**:
   - Функция `categorize_transactions(transactions: list[Transaction]) -> list[Transaction]`.
3. **Зависимости**:
   - `google-genai` (или `google-generativeai`) для общения с Gemini.
   - `python-dotenv` для чтения `.env` файла.

## 4. Тестирование (TDD)
- Поскольку вызовы к реальному API платные и медленные, в unit-тестах (для GitHub Actions) мы будем **мокать** (подменять) ответ от Gemini.
- Добавим отдельный интеграционный тест для проверки реального запроса к Gemini (его можно будет запускать только локально при наличии `.env`).

## 5. Что мы НЕ делаем
- Мы не создаем пока базу данных для сохранения результата.
- Мы не делаем Telegram-бота. Только "мозги", которые размечают данные в оперативной памяти.
