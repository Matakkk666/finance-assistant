# Спецификация: 005-chat-memory (Память Контекста Чата)

## 1. Проблема
Сейчас функция генерации SQL работает только с текущим вопросом пользователя (stateless). Если пользователь задает уточняющий вопрос ("А на что?", "А в прошлом месяце?"), LLM генерирует SQL без учета предыдущих фильтров (дат, категорий), из-за чего выдает неверные результаты за всё время.

## 2. Архитектура решения
Мы добавим сохранение истории сообщений (контекста) для каждого пользователя в оперативную память.
Вместо отправки в Gemini только строки `question`, мы будем отправлять историю переписки (последние 5-6 пар вопрос-ответ).
Таким образом, промпт для генерации SQL будет выглядеть так:
```
Предыдущий контекст:
Пользователь: сколько я потратил за 2-5 августа?
Ответ системы: Вы потратили 19 500 руб.

Текущий вопрос:
Пользователь: на что?

Сгенерируй SQL для текущего вопроса с учетом дат из контекста.
```

## 3. Ограничения
Поскольку это личный бот (1 пользователь), мы можем хранить историю прямо в глобальном словаре `dict` в памяти Python (или использовать встроенный `MemoryStorage` / `FSMContext` библиотеки `aiogram`). Для простоты реализации и независимости сервиса `chat.py`, добавим in-memory хранилище (например, `collections.deque` с ограничением длины) прямо в `src/services/chat.py`.
