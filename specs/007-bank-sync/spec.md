# Спецификация: 007-bank-sync (Синхронизация с онлайн-банком)

## 1. Контекст и проблема
Сейчас пользователю для анализа трат необходимо вручную:
1. Заходить в мобильный банк или личный кабинет.
2. Экспортировать выписку в файл (.csv или .xlsx).
3. Пересылать этот файл боту.

Это создает рутину и замедляет ведение учета.
**Цель фичи:** Научить ассистента напрямую забирать транзакции из онлайн-банка через API по команде пользователя (или по расписанию), категоризировать только новые траты через AI и сохранять их в базу данных.

## 2. Архитектура решения

### Паттерн "Провайдер" (Bank Provider Pattern)
Поскольку у разных банков разные API (Сбер, Т-Банк, МКБ), логика работы с внешними API абстрагируется:
1. `BaseBankProvider` — абстрактный интерфейс с методом:
   `async def fetch_transactions(since_date: date) -> list[Transaction]`
2. `MockBankProvider` — поставщик детерминированных синтетических данных для локальной разработки и непрерывных CI/CD автотестов (без реальных токенов и без сетевых запросов).
3. `TBankProvider` (Т-Банк / Тинькофф) — клиент API Т-Банка с авторизацией по токену.
4. `SberProvider` (Сбер) — клиент API Сбера с авторизацией по токену / сертификату.
5. `MKBProvider` (МКБ — Московский Кредитный Банк) — клиент API МКБ с авторизацией по токену.
6. Фабрика `get_bank_provider(provider_name: str, ...)` — инстанциирует нужного провайдера.

### Поток данных (Data Flow)
```mermaid
flowchart TD
    User([Пользователь]) -->|Команда /sync [банк]| Bot[Telegram Bot]
    Bot -->|Запрос синхронизации| SyncService[BankSyncService]
    SyncService -->|get_bank_provider| Provider[Bank Provider: Сбер / Т-Банк / МКБ / Mock]
    Provider -->|Сетевой запрос / мок| BankAPI[API Банка]
    BankAPI -->|Сырые транзакции| Provider
    Provider -->|list[Transaction]| SyncService
    SyncService -->|Проверка дубликатов| DB[(PostgreSQL)]
    SyncService -->|Только новые транзакции| LLM[Gemini Categorizer]
    LLM -->|Размеченные транзакции| SyncService
    SyncService -->|Сохранение новых| DB
    SyncService -->|Отчет: N новых транзакций| Bot
    Bot -->|Сводное сообщение| User
```

## 3. Требования

### Функциональные требования:
1. **Поддержка банков:**
   - Сбер (`sber`)
   - Т-Банк (`tbank`)
   - МКБ (`mkb`)
   - Тестовый (`mock` — по умолчанию в тестах и при отсутствии токенов)
2. **Дедупликация (Защита от дублей):**
   При повторной синхронизации сервис должен проверять существующие транзакции в БД для данного пользователя (по дате, сумме и описанию) и пропускать уже сохранённые.
3. **Экономия токенов AI:**
   В нейросеть `categorize_transactions` должны передаваться **только новые** транзакции, которых ещё нет в базе данных.
4. **Интерфейс в Telegram-боте:**
   - Команда `/sync` (синхронизирует банк по умолчанию из настроек).
   - Команда `/sync <sber|tbank|mkb|mock>` (позволяет явно указать банк).
   - Бот сообщает статус: `⏳ Подключаюсь к банку...`.
   - Если новых транзакций нет: `✅ Все транзакции уже синхронизированы! Новых записей нет.`.
   - Если есть новые: бот размечает их, сохраняет в БД и выводит отчет: сколько добавлено и распределение по категориям.
5. **Конфигурация:**
   - Переменные окружения в `.env`:
     - `BANK_DEFAULT_PROVIDER="mock"`
     - `TBANK_API_TOKEN=""`
     - `SBER_API_TOKEN=""`
     - `MKB_API_TOKEN=""`

### Требования безопасности:
- Секретные токены банков **никогда** не сохраняются в коде и не коммитятся в git (строго `.env`).
- В CI/CD тестах используется `MockBankProvider` или `unittest.mock` для HTTP-запросов.
