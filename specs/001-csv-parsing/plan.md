# План реализации (Feature 001: Парсинг CSV)

## Подход
Мы будем использовать методологию **TDD (Test-Driven Development)**. Это значит, что для каждого шага мы сначала пишем тест, убеждаемся, что он падает (ведь кода ещё нет), а затем пишем минимальный код, чтобы тест стал зелёным.

## Архитектура фичи
1. **Модель `Transaction`**: Простой Pydantic класс или Dataclass для хранения одной операции (дата, описание, сумма).
2. **Фикстура (Тестовые данные)**: Файл `sample.csv` в папке `tests/fixtures/`, который имитирует реальную выписку.
3. **Парсер `csv_parser.py`**: Функция, которая открывает файл, читает строки, конвертирует типы (строку в дату, строку в float) и возвращает список объектов `Transaction`.

## Риски и особенности
- Формат дат в разных банках разный (например, `DD.MM.YYYY` vs `YYYY-MM-DD`). Для начала захардкодим один простой формат, потом при необходимости добавим гибкость.
- Суммы могут быть с запятой вместо точки (например, `500,50`). Это нужно будет обрабатывать в коде, чтобы Python смог превратить это в число (`float`).
