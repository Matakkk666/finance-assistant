# Спецификация (Feature 001: Парсинг CSV выписки)

## 1. Суть фичи
Пользователь будет отправлять боту файл с выпиской, но прежде чем подключать бота и нейросети, нам нужно научиться извлекать данные из этого файла. Эта фича реализует ядро проекта — парсер, который читает CSV-файл и превращает каждую строчку в Python-объект (модель `Transaction`).

## 2. Требования (Requirements)
- Поддержка чтения `.csv` файлов.
- Извлечение следующих полей из файла:
  - Дата операции (`date`)
  - Сумма операции (`amount`, float, отрицательные — это расходы, положительные — пополнения)
  - Описание/Назначение платежа (`description`)
- Защита от ошибок: игнорирование пустых строк или строк без суммы.
- Независимость от БД на этом этапе (парсер просто возвращает список объектов).

## 3. Технические детали (Design)
1. **Модель данных (`src/models/transaction.py`)**: 
   - Используем `pydantic.BaseModel` или обычный `dataclass` для создания класса `Transaction`.
2. **Логика парсинга (`src/services/parser.py`)**:
   - Функция `parse_csv(file_path: str) -> list[Transaction]`.
   - Будем использовать встроенную библиотеку `csv` (или `pandas`, но для начала хватит `csv`, чтобы не утяжелять проект).

## 4. Тестирование (TDD)
Для разработки по TDD нам понадобится создать фейковый (синтетический) CSV-файл `tests/fixtures/sample.csv`, чтобы не светить реальные данные владельца. Тесты будут проверять:
- Что файл читается без ошибок.
- Что количество извлеченных транзакций совпадает с количеством строк в CSV.
- Что суммы и описания конвертируются правильно (например, строка с суммой "-500.50" становится числом `-500.5`).

## 5. Что мы НЕ делаем в этой фиче
- Подключение базы данных (PostgreSQL). Мы просто возвращаем данные в память.
- Парсинг Excel (`.xlsx`). Пока только CSV.
- Сам Telegram-бот, который принимает файл. Пока пишем только ядро на Python.
