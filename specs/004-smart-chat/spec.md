# Спецификация: 004-smart-chat (Умный Чат / Text-to-SQL)

## 1. Контекст
У нас есть база данных PostgreSQL с транзакциями пользователя. Пользователь хочет задавать естественные вопросы в чат Телеграм (например, "Сколько я потратил на еду в октябре?"), а бот должен отвечать точными цифрами из БД.

## 2. Архитектура решения (Паттерн Text-to-SQL)
Так как транзакций может быть десятки тысяч, мы не можем просто отправлять их все в LLM при каждом вопросе (это дорого и долго). Вместо этого мы научим LLM **писать SQL-запросы**:
1. Бот получает текстовый вопрос от пользователя.
2. Бот отправляет в LLM (Gemini) структуру нашей таблицы `transactions` и вопрос пользователя.
3. LLM возвращает готовый SQL-запрос (например: `SELECT SUM(amount) FROM transactions WHERE category='Еда'`).
4. Бот выполняет этот SQL-запрос в нашей базе (строго в режиме Read-Only).
5. Бот возвращает сырой ответ из БД обратно в LLM с просьбой: "Сформулируй красивый ответ для человека на основе этих данных".
6. Человек получает красивое сообщение в Телеграм.

## 3. Цели (Что нужно сделать)
- Создать сервис `src/services/chat.py`.
- Реализовать генерацию SQL-запроса через Gemini (Prompt Engineering).
- Реализовать безопасное выполнение запроса через SQLAlchemy.
- Обновить обработчик текстовых сообщений в `src/bot/handlers.py`, чтобы бот отвечал на обычный текст (не файлы) через этот новый сервис.

## 4. Ограничения безопасности
- LLM не должна генерировать запросы на изменение данных (`INSERT`, `UPDATE`, `DELETE`, `DROP`). Проверять строку на наличие запрещенных слов перед выполнением.
- Запрос должен всегда фильтроваться по `owner_id` пользователя, чтобы он не мог запросить чужие данные (например, добавлять `WHERE owner_id = X` принудительно, либо строго указывать это в промпте LLM).
