# Спецификация: 003-database (Подключение Базы Данных)

## 1. Контекст и Проблема
В данный момент наш бот парсит выписку, категоризирует транзакции через LLM и сразу отдает текстовый отчет. Данные живут только в оперативной памяти во время обработки и нигде не сохраняются. Это не позволяет нам реализовать фичу "история трат" или "аналитика за прошлый месяц". Нам нужно персистентное хранилище (БД).

## 2. Цели (Что нужно сделать)
1. Развернуть локально базу данных **PostgreSQL** с помощью `docker-compose.yml`.
2. Настроить подключение к БД из FastAPI-приложения, используя асинхронный драйвер (например, `asyncpg`) и **SQLAlchemy**.
3. Настроить систему миграций **Alembic**, чтобы мы могли версионировать структуру БД.
4. Создать таблицу `transactions` в БД.
5. Изменить пайплайн обработки файла: после парсинга и получения ответа от LLM, данные должны сохраняться в БД.

## 3. Вне рамок (Что мы НЕ делаем в этой задаче)
- Мы пока не пишем логику чат-бота, который ищет данные в БД по запросу пользователя. Эта задача только про сохранение.
- Мы не создаем сложную систему пользователей (multi-tenant). Пока все транзакции можно сохранять с привязкой к `telegram_id` владельца.

## 4. Архитектурные решения
- **ORM:** SQLAlchemy 2.0 (современный асинхронный стандарт).
- **Миграции:** Alembic.
- **БД:** PostgreSQL 16 (в Docker).
- **Схема данных (сущность Transaction):**
  - `id` (Primary Key, UUID или Integer)
  - `owner_id` (Integer, ID пользователя в Телеграм)
  - `date` (DateTime)
  - `amount` (Float)
  - `description` (String)
  - `category` (String)
