# ADR 0001: Выбор технологического стека

**Дата:** 2026-10-07
**Статус:** Принято

## Контекст
Для старта разработки финансового ассистента необходимо выбрать основной стек технологий (язык, фреймворки, базу данных), который обеспечит баланс между скоростью разработки MVP и возможностью масштабирования в будущем. Рассматривались варианты с SQLite (как наиболее простые) и PostgreSQL, а также облачные решения.

## Рассмотренные варианты
1. Python + FastAPI + SQLite
2. Python + FastAPI + PostgreSQL (в Docker)
3. Python + Supabase (BaaS)

## Решение
Выбран **Вариант 2**: 
- **Язык**: Python 3.12+
- **Бэкенд**: FastAPI
- **Telegram Бот**: aiogram 3.x
- **База данных**: PostgreSQL
- **ORM**: SQLAlchemy
- **Инфраструктура**: Docker / Docker Compose

## Обоснование
Владелец проекта обладает собственным виртуальным сервером (VPS), что снимает сложность хостинга базы данных. Выбор PostgreSQL обеспечивает максимальную надежность хранения чувствительных финансовых данных, соответствует стандартам индустрии и позволяет избежать проблем с блокировками (concurrency), которые могли бы возникнуть в SQLite при одновременной записи в БД от Telegram-бота и запросах от веб-дашборда. 

Связка FastAPI + aiogram позволяет держать асинхронный код бота и REST API в одной кодовой базе, что упрощает разработку и поддержку на этапе MVP. Docker Compose будет использоваться для локальной разработки и последующего деплоя на VPS.
